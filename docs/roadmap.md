Released history belongs in [CHANGELOG.md](../CHANGELOG.md), implementation history remains in Git, and detailed compatibility evidence belongs under [`docs/compatibility/`](compatibility/).

### [#8: Fix sustained MQTT report pump overflow/resync churn](https://github.com/ProjectPandar/pandar/issues/8)

The software scope is complete:

- Agent overflow warnings identify the printer serial and dropped report count while preserving loss-triggered full resynchronization.
- Hub snapshot validation remains ordered and fail-fast, while current-session aggregate application and event fanout run with bounded concurrency.
- Command results, print reports, and other non-snapshot events retain their ordered fail-fast behavior.
- Hermetic regressions cover warning attribution, slow snapshot fanout, and current-session fencing.

Live deployment follow-up: with the concurrent Hub and attributed warnings deployed, every printer still overflowed on a ~45 s cycle while job reports flowed normally — the attributed serials plus zero report-consumer restarts identified the actual source as each printer's command-role MQTT connection, which subscribes to `device/{serial}/report` during operations and never unsubscribes, leaving a queue nobody reads. The prescribed firmware transition-mutex audit was performed and cleared (those locks are only held across channel sends while the shared channel drains). The pump overflow policy is now per role: report-role connections keep the fail-the-consumer-for-resync contract, while command-role queues shed the oldest entry on overflow so a fresh command response is never discarded.

Remaining acceptance work:

- After deploying the current Hub and Agent, run a sustained print on one printer with the other linked printers idle.
- Confirm the Agent records zero pump-overflow warnings.
- Record the live result in issues #7 and #8 before closing #8.

## Recently Completed

- Fixed intermittent `500 internal_server_error` on `DELETE /api/v1/tenants/{tenant_id}/agents/{agent_id}` (and on credential rotate/revoke) with the SQLite backend: `delete_offline_with_audit`, `rotate_credential`, and `revoke_credential` read the agent row inside a deferred `BEGIN` transaction before their first write, so any concurrent commit (live printer snapshots, heartbeats, another agent's writes) landing between the `SELECT` and the write made SQLite fail the lock upgrade with `database is locked` (the busy handler is not consulted for `SQLITE_BUSY_SNAPSHOT`). They now start with `begin_write_transaction()` (`BEGIN IMMEDIATE` on SQLite, unchanged on PostgreSQL) like the other read-modify-write flows; a stress reproduction (concurrent writer, 2000 deletes) went from 3 failures to 0.

- Fixed Agents stuck `online` after a hub restart (`409 agent_online`, delete button disabled): `SessionRegistry::expire_stale` only sees this instance's in-memory sessions, so an agent that was online when its instance restarted or crashed and never reconnected stayed `online` forever. The 15s expiry loop now also runs `AgentRepository::expire_orphaned_online_sessions`, which retires persisted online sessions whose `last_seen_at` is older than the same 45s cutoff through `mark_offline_if_current` (a session reclaimed meanwhile is left alone), so it is safe with several hub instances, and publishes the printers projection change. Tests: the runtime tick retires a stale orphan while leaving a fresh one online; through the public API an agent claimed online with no registered session returns `409 agent_online`, then `200` once the real `spawn_session_expiry` loop has run.

- Replaced the Devices printer-card grid with a printer console (design: `design/pandar-hub-frontend`): a searchable, filterable printer list next to the selected printer's live detail, which keeps every former card control (inline camera preview with picture-in-picture and fullscreen, print controls, print speed, axis moves, temperatures, cooling, HMS, materials, H2C rack) and adds compatibility facts plus that printer's newest jobs with retry-dispatch, reprint, and delete. On phones the detail replaces the fleet overview and the shell header becomes a back navigation (`useShellHeaderOverride`). Diagnostics results render as a checklist — status icon plus message with the check id and details as secondary text, abnormal rows highlighted — and compatibility rows use the same status icons. Job deletion is shared through `useJobDelete`; `dashboard-printer-card.tsx` was removed.

- Added Hub web sign-in for browser apps on a `PANDAR_CORS_ALLOWED_ORIGINS` origin, such as the Ares slicer web app, mirroring the Android ticket flow. `/web-sign-in?redirect_url=&code_challenge=&state=` reuses the mobile tenant-selection page (no default callback; a missing `redirect_url` shows an error state) and redirects to the callback with `ticket`, `redirect_url`, and `state`. `POST /api/v1/tenants/{tenant_id}/web/login-tickets` accepts only `http(s)` callbacks without userinfo, query, or fragment whose origin exactly matches an allowlist entry, and the CORS-enabled `POST /api/v1/web/login-tickets/exchange` checks PKCE S256 and issues a 30-day `web:session` tenant token (`pandar_web_`) that, like `mobile:session`, acts with the signed-in user's current role and cannot be minted manually.
